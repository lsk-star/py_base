# PyBase 分包、分层与启动流程指南

本文面向第一次使用 PyBase 的开发者。目标是让新增业务时有明确的位置可放，且不会因为增加一个模块而破坏应用核心。

## 一、先理解四个边界

```text
HTTP 请求
    ↓
presentation（协议适配）
    ↓
modules（业务用例）
    ↓
infrastructure / 外部系统（具体技术实现）
```

- `core`：应用运行所必需的基础能力，例如配置、日志、错误码和上下文。
- `presentation`：只处理 HTTP 相关问题，例如路由、请求参数、响应格式、异常映射和中间件。
- `modules`：按业务能力组织代码。业务规则应该在这里，而不是散落在路由函数或数据库模型里。
- `infrastructure`：数据库、缓存、消息队列、对象存储等第三方技术的具体实现。

## 二、如何分包

### 1. 新增业务模块

例如新增用户模块：

```text
src/pybase/modules/user/
├── __init__.py
├── router.py       # HTTP 路由和依赖注入
├── schemas.py      # Pydantic 请求、响应模型
├── service.py      # 用户业务用例、事务边界
├── repository.py   # 用户数据访问；只有确实需要替换或测试隔离时才抽象
└── models.py       # 该模块的数据库模型（也可集中放到 database/models）
```

推荐调用关系：

```text
router → service → repository → SQLAlchemy
```

路由不直接写 SQL；服务不负责解析 HTTP；仓储不负责决定 HTTP 状态码。这样每一层都能单独测试。

### 2. 何时创建 contracts

只有以下情况才创建契约：

- 将来确实要替换实现，例如本地文件存储和云对象存储。
- 需要隔离第三方 SDK，避免业务层直接依赖 SDK。
- 测试需要注入假的实现。

不要为只有一个实现的普通服务创建 `IFooService`、`FooServiceImpl` 两层。契约应该描述稳定的能力边界，而不是复制类名。

### 3. application.py 的职责

所有能力都应在 [application.py](../src/pybase/application.py) 中显式装配：

1. 读取配置。
2. 配置日志。
3. 创建可选组件。
4. 注册中间件、异常处理器和路由。
5. 声明启动、运行、关闭生命周期。

不要在路由模块导入时创建数据库连接、Redis 客户端或后台任务。这样会导致测试导入即产生副作用，也会让未启用的能力无法真正移除。

### 4. 使用模块生成器

模块生成器只生成统一的分层骨架，不猜测 `email`、`password`、`status` 等业务字段，也不生成
没有业务语义的 CRUD HTTP 接口。

```powershell
# 生成基础模块
uv run pybase generate module user

# 生成带数据库模型和仓储层的模块
uv run pybase generate module user --with-model

# 只预览将创建或修改的文件
uv run pybase generate module user --with-model --dry-run

# 基础模块后续追加数据库能力
uv run pybase generate module user --with-model
```

基础命令生成：

```text
src/pybase/modules/user/
├── __init__.py
├── router.py
├── schemas.py
├── service.py
└── README.md

tests/modules/user/
├── __init__.py
└── test_module.py
```

- `router.py`：包含 `APIRouter`、统一的路由前缀和标签，不自动创建业务接口。
- `schemas.py`：包含可复用的 Pydantic 模型基类；字段由业务需求决定。
- `service.py`：包含模块日志对象，负责业务用例和事务边界。
- `README.md`：模块职责和分层约束。
- `test_module.py`：模块路由基础回归测试。

`--with-model` 额外生成：

```text
src/pybase/modules/user/
├── models.py
├── repository.py
└── dependencies.py
```

生成的模型继承 `IntIdMixin, Base`。`IntIdMixin` 在
`infrastructure/database/base.py` 统一提供自增整数主键，因此生成器不会在每个模型中重复定义
`id`。特殊的 UUID、联合主键或关联表模型可以只继承 `Base`，不使用该 Mixin。

生成的 Repository 提供通用的 `create`、`get_by_id`、`exists_by_id`、`count`、`get_page`、`update`、
`delete`、`delete_by_id` 方法：

- 不调用 `commit()`，事务由 Service 管理。
- 分页稳定按 `id` 升序，不假设业务排序字段。
- `update()` 接收实体，避免根据任意字典更新字段。
- `delete_by_id()` 先按 ID 查询，再删除实体；实体不存在返回 `False`，不会抛出无意义的异常。
- `exists_by_id()` 和 `count()` 适合列表页、权限校验等通用场景。
- 不生成 `get_by_email()` 等业务专属查询。

生成的 Service 已提供 `get_by_id`、`create`、`update`、`delete_by_id` 示例用例。它们只演示
通用的事务编排，不代表系统必须提供对应的 HTTP 接口；业务字段和接口仍由开发者补充。

基础模块的 `schemas.py` 会生成一个带 `from_attributes=True` 的 Pydantic 基类，便于从 ORM 实体
转换响应。它不包含 `name`、`email` 等猜测字段。`router.py` 只生成路由对象和依赖注入示例注释，
避免脚手架替业务决定 API 语义。

生成器会自动更新两个受保护区域：

```text
src/pybase/modules/registry.py
src/pybase/infrastructure/database/models/__init__.py  # 仅 --with-model
```

基础模块的 Router 会正常注册；带 `--with-model` 的模块标记为 `requires_database=True`，只有
`database.enabled=true` 时才延迟导入。因此最小依赖模式不会导入 SQLAlchemy。

默认路由前缀和表名使用模块名原样，例如 `user`。可按需要覆盖：

```powershell
uv run pybase generate module user_profile `
  --route-prefix users `
  --table-name user_profiles `
  --with-model
```

生成器拒绝非法模块名、已有模块目录和缺少受保护标记的项目文件，默认不覆盖已有代码。

生成器支持非破坏性增量升级。以下流程是安全的：

```powershell
uv run pybase generate module user
# 开发者可以先补充 Router、Schema 和业务方法
uv run pybase generate module user --with-model
```

第二条命令只会创建缺失的 `models.py`、`repository.py`、`dependencies.py`，并更新模块注册、
Alembic 模型导入和 Service 中的受保护区域；不会覆盖已有 Router、Schema、README、测试或 Service
中受保护区域以外的业务方法。重复执行同一命令是幂等的，不会产生重复的路由注册和模型导入。

基础 Service 模板含有以下受保护标记：

```text
# pybase: generated service imports - start
# pybase: generated service imports - end

    # pybase: generated database setup - start
    # pybase: generated database setup - end
```

若 Service 来自更早版本、标记被删除，或文件无法安全升级，生成器会终止且不写入任何文件。确认需要
让生成器覆盖该 Service 时，才显式使用：

```powershell
uv run pybase generate module user --with-model --force
```

`--force` 只覆盖冲突的 `service.py`，不覆盖 Router、Schema、Repository、Model 等已有文件。

## 三、如何接入新的数据库

当前数据库边界使用 SQLAlchemy 2.x 异步引擎。应用代码依赖 `AsyncSession`、ORM 和 SQLAlchemy 方言，不直接依赖某个数据库厂商的 SDK。

安装方式按数据库选择：

```powershell
# 只安装 SQLAlchemy/Alembic 核心
uv sync --extra database

# PostgreSQL
uv sync --extra database-postgresql

# SQLite（本地测试）
uv sync --extra database-sqlite

# MySQL/MariaDB
uv sync --extra database-mysql
```

对应配置示例：

```env
# PostgreSQL
PYBASE_DATABASE__URL=postgresql+asyncpg://user:password@localhost:5432/example

# SQLite
PYBASE_DATABASE__URL=sqlite+aiosqlite:///./example.db

# MySQL
PYBASE_DATABASE__URL=mysql+asyncmy://user:password@localhost:3306/example
```

适配新数据库时通常只需要三件事：

1. 安装 SQLAlchemy 支持的异步方言驱动。
2. 使用对应的 SQLAlchemy URL。
3. 如有厂商特有 SQL，在仓储或迁移中隔离，不把厂商逻辑泄漏到通用业务层。

`DatabaseComponent` 负责引擎创建、连接探测、连接池释放和 readiness；业务模块通过 session factory 或仓储使用数据库。Alembic 迁移会自动移除异步驱动后缀，使用同步迁移引擎执行。

如果用户不想使用 SQLAlchemy，也可以新增另一套实现：保留同样的生命周期与 readiness 边界，在 `application.py` 根据配置选择实现。不要在业务代码中判断 `if postgres / if mysql`。

### 1. 数据库组件如何桥接到 FastAPI 依赖

`DatabaseComponent` 在应用生命周期中只创建一个全局 `session_factory`，它是创建
会话的工厂，不是可跨请求复用的 `AsyncSession`。每个 HTTP 请求通过
`infrastructure/database/dependencies.py` 创建和关闭自己的 Session：

```text
Router → Service → Repository → AsyncSession
                              ↑
                    get_db_session（每个请求）
                              ↑
            DatabaseComponent.session_factory（全局工厂）
```

`ComponentRegistry.get()` 是这层桥接的组件查询入口：

```python
from typing import TypeVar, cast

T = TypeVar("T")


def get(self, component_type: type[T]) -> T:
    for component in self._components:
        if isinstance(component, component_type):
            return cast(T, component)
    raise LookupError(f"组件未注册: {component_type.__name__}")
```

数据库依赖的实际实现如下。数据库未启用或尚未启动时，返回统一的 503 异常，而不是
让 `LookupError` 或 `RuntimeError` 变成 500：

```python
from collections.abc import AsyncIterator

from fastapi import Request
from sqlalchemy.ext.asyncio import AsyncSession

from pybase.core.exceptions import DependencyUnavailableError
from pybase.infrastructure.database.component import DatabaseComponent


async def get_db_session(request: Request) -> AsyncIterator[AsyncSession]:
    try:
        database = request.app.state.components.get(DatabaseComponent)
    except LookupError as exc:
        raise DependencyUnavailableError("数据库能力未启用") from exc

    if database.session_factory is None:
        raise DependencyUnavailableError("数据库尚未就绪")

    async with database.session_factory() as session:
        yield session
```

### 2. 业务模块如何使用 Session

在业务模块中建立以下目录：

```text
src/pybase/modules/user/
├── router.py          # FastAPI Depends 注入 Session
├── service.py         # 事务边界和业务规则
├── repository.py      # 只执行数据访问
├── schemas.py
└── models.py
```

Repository 只接收 `AsyncSession`，绝不能读取 `request` 或 `app.state`：

```python
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession

from .models import User


class UserRepository:
    def __init__(self, session: AsyncSession) -> None:
        self._session = session

    async def get_by_email(self, email: str) -> User | None:
        result = await self._session.execute(select(User).where(User.email == email))
        return result.scalar_one_or_none()

    def add(self, user: User) -> None:
        self._session.add(user)
```

Service 持有事务边界；Repository 不应调用 `commit()`：

```python
class UserService:
    def __init__(self, session: AsyncSession) -> None:
        self._session = session
        self._repository = UserRepository(session)

    async def create_user(self, email: str) -> User:
        async with self._session.begin():
            user = User(email=email)
            self._repository.add(user)

        await self._session.refresh(user)
        return user
```

Router 使用 `Annotated` 和 `Depends` 注入请求级 Session：

```python
from typing import Annotated

from fastapi import APIRouter, Depends
from sqlalchemy.ext.asyncio import AsyncSession

from pybase.infrastructure.database.dependencies import get_db_session

SessionDep = Annotated[AsyncSession, Depends(get_db_session)]
router = APIRouter(prefix="/users")


@router.post("")
async def create_user(email: str, session: SessionDep):
    return await UserService(session).create_user(email)
```

### 3. 保持数据库能力可选

`dependencies.py` 依赖 SQLAlchemy，因此只能由数据库业务模块导入。数据库业务路由也必须
仅在数据库能力启用后注册；不要在核心路由模块的顶层无条件导入 `modules.user.router`。

推荐在 `application.py` 的应用装配阶段，先验证并装配数据库组件，再根据
`settings.database.enabled` 延迟导入和注册数据库业务路由。这样执行 `uv sync` 的最小
安装仍可正常启动，不会因缺少 SQLAlchemy 而导入失败。

## 四、如何新增外部基础设施：以 Redis 为例

Redis 是可选能力，应该遵循与数据库完全相同的规则：未安装且未启用时应用必须正常启动；只有启用 Redis 后才检查依赖和配置。

### 1. 推荐目录

```text
src/pybase/
├── core/config.py                         # RedisSettings
├── contracts/cache.py                     # 只有需要替换或测试隔离时才定义
└── infrastructure/redis/
    ├── __init__.py
    └── component.py                       # 连接、关闭、readiness
```

业务模块只依赖 `Cache` 契约或由依赖注入提供的缓存对象，不能直接在 `router.py` 里创建 `redis.Redis()`。

### 2. 新增独立配置

在 `core/config.py` 添加：

```python
class RedisSettings(BaseModel):
    enabled: bool = False
    url: str | None = None
    strict_startup: bool = True


class Settings(BaseSettings):
    # 保留已有配置...
    redis: RedisSettings = RedisSettings()
```

`.env` 中使用模块化变量：

```env
PYBASE_REDIS__ENABLED=true
PYBASE_REDIS__URL=redis://127.0.0.1:6379/0
PYBASE_REDIS__STRICT_STARTUP=true
```

### 3. 新增 optional extra

在 `pyproject.toml` 添加，不把 Redis 放到核心 `dependencies`：

```toml
[project.optional-dependencies]
redis = ["redis[hiredis]>=5.0,<7.0"]
```

使用者只在需要时安装：

```powershell
uv sync --extra redis
```

### 4. 仅在有替换价值时定义契约

缓存后端常有本地内存、Redis、测试假实现，因此契约有价值。创建
`contracts/cache.py`：

```python
from typing import Protocol


class Cache(Protocol):
    async def get(self, key: str) -> bytes | None: ...
    async def set(self, key: str, value: bytes, *, ttl_seconds: int | None = None) -> None: ...
    async def delete(self, key: str) -> None: ...
```

如果 Redis 只是某个基础设施内部的实现细节、业务层永不替换它，就不必创建这个契约。

### 5. 实现生命周期组件

`infrastructure/redis/component.py` 应实现 `LifecycleComponent`，模式与数据库组件一致：

```python
from redis.asyncio import Redis, from_url

from pybase.contracts.lifecycle import ReadinessStatus
from pybase.core.exceptions import ConfigurationError


class RedisComponent:
    name = "redis"

    def __init__(self, settings) -> None:
        if not settings.url:
            raise ConfigurationError("Redis 已启用，但未配置 PYBASE_REDIS__URL")
        self._settings = settings
        self.client: Redis | None = None

    async def start(self) -> None:
        self.client = from_url(self._settings.url)
        try:
            await self.client.ping()
        except Exception:
            if self._settings.strict_startup:
                await self.stop()
                raise

    async def stop(self) -> None:
        if self.client is not None:
            await self.client.aclose()
        self.client = None

    async def readiness(self) -> ReadinessStatus:
        try:
            ready = self.client is not None and bool(await self.client.ping())
            return ReadinessStatus(self.name, ready)
        except Exception as exc:
            return ReadinessStatus(self.name, False, str(exc))
```

### 6. 只在 application.py 装配

在 `_build_components()` 中添加与数据库同样的显式分支：

```python
if settings.redis.enabled:
    try:
        from pybase.infrastructure.redis.component import RedisComponent
    except ImportError as exc:
        raise ConfigurationError(
            "Redis 已启用，但未安装依赖。请执行: uv sync --extra redis"
        ) from exc
    registry.add(RedisComponent(settings.redis))
```

这一步将 Redis 纳入应用启动、关闭和 `/ready`，而 `/live` 永远不会因 Redis 故障失败。MQ、对象存储、邮件服务也使用同一流程：**配置 → extra → 必要契约 → 实现 → 生命周期 → 应用工厂装配**。

## 五、Alembic 数据库迁移

Alembic 是数据库结构版本管理工具。它需要安装对应数据库 extra、有效的
`PYBASE_DATABASE__URL`，但不要求运行中的 FastAPI 服务。

### 1. 新建模型

以用户表为例，创建 `src/pybase/infrastructure/database/models/user.py`：

```python
from datetime import datetime

from sqlalchemy import DateTime, String
from sqlalchemy.orm import Mapped, mapped_column

from pybase.infrastructure.database.base import Base


class User(Base):
    __tablename__ = "users"

    id: Mapped[int] = mapped_column(primary_key=True)
    email: Mapped[str] = mapped_column(String(255), unique=True, index=True)
    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True))
```

然后在 `src/pybase/infrastructure/database/models/__init__.py` 导入模型：

```python
from pybase.infrastructure.database.models.user import User

__all__ = ["User"]
```

没有这一步，Alembic 不会看见 `User`，自动生成的迁移会是空的。

### 2. 生成和审查迁移

```powershell
# 基于 Base.metadata 与实际数据库的差异生成迁移草稿
uv run alembic revision --autogenerate -m "create users"

# 查看当前数据库版本
uv run alembic current

# 查看所有迁移历史
uv run alembic history
```

迁移文件生成在 `migrations/versions/`。**必须人工审查** `upgrade()` 和
`downgrade()`，特别是删除列、数据迁移、索引、枚举和生产大表操作。自动生成只是一份草稿。

### 3. 执行与回滚

```powershell
# 升级到最新版本
uv run alembic upgrade head

# 升级一个版本
uv run alembic upgrade +1

# 回滚一个版本
uv run alembic downgrade -1

# 标记现有数据库版本，不执行 SQL；仅用于已人工对齐的数据库
uv run alembic stamp head
```

生产环境建议将 `alembic upgrade head` 作为单独的发布步骤或 Job 执行，不要由每个 Web 进程启动时自动执行迁移，以免多实例并发修改表结构。

### 4. 多数据库注意点

`migrations/env.py` 会把异步 URL（例如 `postgresql+asyncpg://`）转换为与已安装驱动匹配的同步迁移 URL（`postgresql+psycopg://`）。因此 PostgreSQL extra 同时包含 `asyncpg` 和 `psycopg`；MySQL extra 同时包含 `asyncmy` 和 `PyMySQL`。应用运行与迁移都可以使用同一份 `PYBASE_DATABASE__URL`。

## 六、从启动到关闭发生了什么

### 导入阶段

执行 `uv run pybase` 后，入口在 `pybase.main`：

1. 导入 `create_application`。
2. 创建全局 `app` 对象。
3. `create_application` 读取 `Settings`。配置来自环境变量和 `.env`，使用 `PYBASE_模块__字段` 命名。
4. 配置根日志处理器。
5. 根据 `database.enabled` 决定是否导入并创建数据库组件。关闭时不会导入 SQLAlchemy。
6. 创建 FastAPI 应用，注册请求上下文和访问日志中间件、异常处理器、`/live`、`/ready` 和 `/api/v1` 路由。

### 启动阶段

Uvicorn 进入 FastAPI lifespan：

1. `ComponentRegistry.start()` 按注册顺序启动组件。
2. 数据库组件创建异步引擎和 session factory。
3. 数据库执行 `SELECT 1` 验证连接。
4. 严格启动模式下，连接失败会停止已启动组件并拒绝应用启动；宽松模式下应用继续运行，但 `/ready` 返回 503。

### 请求阶段

1. `RequestContextMiddleware` 读取或生成 `request_id`，写入 `ContextVar` 并在响应头回写 `X-Request-ID`。
2. `AccessLogMiddleware` 记录请求方法、路径和脱敏后的查询参数；响应时记录状态码和耗时。访问日志执行期间可以从上下文自动得到 `request_id`。
3. FastAPI 匹配路由并执行业务代码。
4. 成功响应和异常响应都通过统一响应模型返回，并附带 `request_id`。
5. 中间件将 `request_id` 写入响应头，然后清理上下文。

默认不生成 `trace_id`。只有 `PYBASE_TRACING__ENABLED=true` 时，应用才透传上游的 `X-Trace-ID` 或 W3C `traceparent`；这为后续接入 OpenTelemetry 保留了边界，但不将两个随机 ID 混为一谈。

### 关闭阶段

Uvicorn 触发 lifespan 退出：

1. `ComponentRegistry.stop()` 按注册顺序的逆序释放资源。
2. 数据库调用 `engine.dispose()` 关闭连接池。
3. 应用记录停止日志并结束进程。

## 七、中间件分包与日志规范

中间件按职责拆分，目录如下：

```text
src/pybase/presentation/middleware/
├── request_context.py    # request_id 与可选 trace_id 的上下文和响应头
├── access_log.py         # 请求、响应、耗时与参数脱敏日志
└── registration.py       # 唯一的中间件注册位置和执行顺序
```

应用工厂只调用 `register_middlewares(app)`。不要在模块内部随意调用 `app.add_middleware()`，否则中间件顺序会变得不可见。

当前注册后的请求执行顺序为：

```text
RequestContextMiddleware
    ↓
AccessLogMiddleware
    ↓
路由 / 异常处理
```

请求日志示例：

```text
[request_id=req_123] 请求 method=GET path=/api/v1/users query={'page': '1'}
```

响应日志示例：

```text
[request_id=req_123] 响应 method=GET path=/api/v1/users status_code=200 duration_ms=12.40
```

查询参数中的 `password`、`token`、`secret`、`authorization`、`cookie`、`api_key`、OAuth `code` 等会替换为 `***`，值会限制最大长度。默认不记录请求体。

就绪探针中，任何单个组件的检查异常都会被转换为该组件的未就绪状态，`/ready` 返回 503 而不是 500。组件关闭时则会继续释放其余组件；若多个组件关闭失败，应用会在全部清理尝试结束后报告聚合错误。

## 八、排查 `/docs` 显示旧项目

本项目的 FastAPI 标题来自 `PYBASE_APP__NAME`，默认是 `PyBase`。如果 `/docs` 显示旧项目，通常不是 OpenAPI 缓存，而是请求没有到达当前应用：

```powershell
# 查看 8000 端口的占用进程
Get-NetTCPConnection -LocalPort 8000 -State Listen

# 推荐从项目根目录启动，确保使用当前 pyproject.toml
uv run pybase

# 查看当前应用元数据
Invoke-RestMethod http://127.0.0.1:8000/openapi.json
```

如果 `openapi.json` 的 `info.title` 不是 `PyBase`，先停止旧进程，再重新启动本项目。也可以显式执行：

```powershell
uv run uvicorn pybase.main:app --host 127.0.0.1 --port 8000
```

不要在另一个旧项目目录中执行 `uvicorn main:app`，也不要混用全局 Python 与项目的 uv 环境。

如果旧服务暂时不能停止，在 `.env` 中设置 `PYBASE_APP__PORT=8001`，然后访问
`http://127.0.0.1:8001/docs`。监听端口由 `AppSettings` 管理，启动入口会读取该配置。
